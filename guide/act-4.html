Rerank, Prompt and Answer

Search hands you the chunks nearest the question, not the ones that answer it. You add a reranker that reads the question and each chunk together and sorts them again, build a prompt from the best few with each one numbered, and get back an answer that cites the night and moment, or the document, every fact came from. Then you ask your pipeline a question.

1 Add rerank

Open src/rerank.ts. An embedding turns the question and each chunk into vectors separately, so search only knows they're about similar things. A reranker is a cross-encoder. It reads the question and one chunk as a single input and scores how well the chunk answers it. It's Xenova/ms-marco-MiniLM-L-6-v2, already in your codespace, and it needs no key. It reads at most 512 tokens at once, which is why Act 2's chunk sizes stop where they do.

Why each numbered part is there. Point at one to see its lines.
(1) Depth is a hard cut. A hit past depth is never scored, so it can't reach the prompt however well it answers. The last hour's wrong game night turns on this line.
(2) Question and chunk, read together. The reranker sees which words in the chunk answer which words in the question, which two separate vectors can't. It's slower than a vector search, so it gets your few hits, never the whole store.
(3) The score decides the order now. Each chunk keeps its score, from 0 to 1, and the best comes first. The last hour's relevance gate reads the best score to decide whether to answer at all.

Why each numbered part is there. Point at one to see its lines.
(6) JSON in a fixed shape, not prose. answerFormat is a strict schema, so the provider holds the model to it and JSON.parse never meets free text. Without it you'd be fishing source numbers out of sentences.
(7) Numbers back to chunks, checked. The prompt numbers from 1, so number n is chunks[n - 1]. A model can cite a source the prompt never held, and the filter drops its undefined.
(8) The citation comes from the row. The night and moment are copied from the chunk the store returned, never from what the model wrote. The last hour's eval reads these citations to check each answer used the right source.

4 Choose your depth, chunks kept and refusal

Open src/choices.ts and fill in the three Act 4 values.

  • RERANK_DEPTH is how many of your RETRIEVAL_K hits the reranker scores. Deeper finds an answer search ranked low, and costs a little time on every question.
  • CHUNKS_KEPT is how many of the best go into the prompt. Each one costs input tokens on every question, and a weak one gives the model something wrong to lean on.
  • REFUSAL_INSTRUCTION is what the model is told to do when the sources don't hold the answer. Write it in your own words. The last hour tests it.
