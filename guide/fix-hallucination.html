Hallucinated NPCs

A pipeline that always answers will answer questions it has nothing for. You ask yours about an NPC who never sat at the table, a name Whisper misheard and a roll nobody wrote down, and see what comes back. Then you add two fixes: a relevance gate that says "I don't know" before the model is ever called, and a refusal instruction you rewrite. Each fix catches a different ask.

Done when

  • npm test -- fix-hallucination passes
  • the Madam Eva question gets "I don't know" without asking the model
  • a rewritten REFUSAL_INSTRUCTION
  • your threshold on the Retrieval line in DECISIONS.md

1 Ask three questions it can't answer

Ask each of these as katie, who sits at both tables:

npm run ask -- --user katie "What did Madam Eva read in the cards?"
npm run ask -- --user katie "What does Glinsky sell?"
npm run ask -- --user katie "Who rolled the natural 20?"

Read the answer, then the scores under it. The reranker scores from 0 to 1, and the best chunk comes first.

  • Madam Eva reads fortunes in the published adventure, and she never appeared at this table. No chunk mentions her, so the best score is tiny, with several zeros after the point. Whatever the model says, it isn't from your nights.
  • Glinsky is how Whisper heard Blinsky in one passage of the first Barovia night. A chunk really does say "Glinsky", so it scores well, and the model answers with what Blinsky sells. The mistake is Whisper's, and no fix on this page can see it.
  • The natural 20 was rolled, and the transcripts have no diarization, so no segment says who rolled it. Chunks about rolling dice score high, near 1, and none holds the answer.

2 Ask one of them three times

Run the natural 20 question three times:

npm run ask -- --user katie "Who rolled the natural 20?"

The chunks and their scores barely move between runs. The answers do. One run may say "I don't know", another may explain that the sources don't name anyone, and another may cite chunks for an answer they don't hold. openai/gpt-4o-mini picks each word by sampling, so one prompt can come back worded differently, or decided differently.

There's no temperature setting to turn down here, on purpose. Turning it down narrows the sampling, but hosted models still don't promise the same answer twice. Plan for an answer that varies. The last hour's eval asks every question three times for this reason.

3 Add passesGate

Open src/gate.ts. The relevance gate runs after the reranker and before the prompt. When even the best chunk scores under your threshold, ask answers "I don't know" without calling the model at all. The gate reads the reranker's score, from Xenova/ms-marco-MiniLM-L-6-v2, because it read the question and the chunk together. Vector distance only says how near two things sit.

In src/gate.ts, replace this line with the code below it:

Why each numbered part is there. Point at one to see its lines.
(1) The reranker's score, never distance. The nearest chunk to a question about Madam Eva is still near something, so distance can't say that nothing answers it. The reranker read each chunk with the question, so a low best score can.
(2) Under the threshold, no answer call. When this returns false, ask answers "I don't know" with no citations and never builds the prompt. That's the answer call you don't pay for.

4 Choose your threshold

Open src/choices.ts and set RELEVANCE_THRESHOLD. A best score under it gets "I don't know".

Use the scores from step 1. Most chunks in a chatty transcript score far under 0.1, and the chunk that holds a real answer can score under 0.01. Put the threshold above Madam Eva's best score and under the best score of the questions your pipeline answers, such as the Blinsky question. Too high, and your pipeline refuses questions it could answer. Too low, and nothing gets stopped.

5 Run the tests 

npm test -- fix-hallucination

Until RELEVANCE_THRESHOLD is set, one test fails and tells you to pick it. The rest check the gate on a few made-up scores, then build the small index from Act 4 and ask two real questions. The Madam Eva question has to come back "I don't know" with no answer call in the cost log. The Blinsky question has to get through to one answer call.

6 Ask again 

npm run ask -- --user katie "What did Madam Eva read in the cards?"

Under the answer, npm run ask now says the best score is under your threshold, so the model wasn't asked. That's one answer call you didn't pay for, and one answer you didn't have to trust the model for.

Ask the other two again. Both still get through, because each has a chunk that scores well. The gate can't tell a misheard name from a right one, and it can't tell a chunk about rolling dice from a chunk that names who rolled. The second fix is in the prompt.

7 Rewrite your refusal instruction

Open src/choices.ts and rewrite REFUSAL_INSTRUCTION, the text you wrote in Act 4. Make it stricter in your own words. Ideas that worked for the presenter:

  • Answer only from the numbered sources, never from what the model knows about Dungeons & Dragons or its published adventures.
  • When no source says the answer outright, answer exactly "I don't know." and list no sources.

Ask the natural 20 question three times again. Then ask a question that does have an answer: 

npm run ask -- --user katie "Who did the banshees at the windmill look like?"

A stricter instruction refuses more, and some of what it refuses had an answer. Check that it still answers this one and the Blinsky question. Loosen a word if it doesn't.
