Clean and Chunk the Nights

Whisper's segments are too short to search one at a time, and they come with its mistakes in them. You clean them into records that know their night, their campaign and who may see them, then cut each night into chunks of whole segments, at a size and overlap you choose.

1 Add clean

Open src/clean.ts. Cleaning turns a night's segments into records: the text, when it was said, which night and campaign it's from, and who may see it.

It also fixes one of Whisper's habits. On a long stretch of table noise it can get stuck and write the same segment again and again. In Toe Wittine's first game night it wrote Over-packed a little bit. 277 times in a row.

1  // (1) A night is its campaign's party: whatever the DM says at the table,2  // the players heard.3  const visibility = `${night.campaign}/party`;4  const records: SegmentRecord[] = [];5  for (const segment of night.segments) {6    // (2) whisper.cpp starts every segment with a space.7    const text = segment.text.trim();8    // (3) A repetition loop: Whisper writes the same segment again and again.9    // Keep the first.10    if (text === records.at(-1)?.text) continue;11    records.push({12      night: night.id,13      start: segment.offsets.from,14      end: segment.offsets.to,15      campaign: night.campaign,16      visibility,17      text,18    });19  }20  return records;
Why each numbered part is there. Point at one to see its lines.
(1) Visibility from the campaign. Every night gets <campaign>/party, because whatever the DM says at the table, the players heard. DM-only content lives in DM documents instead, and the last hour's filter reads this field.
(2) Trim the space. whisper.cpp starts every segment with one. Trimmed, two copies of the same words compare equal, and the chunker counts only the characters a reader sees.
(3) Collapse the loop. Only a run in a row collapses, since the same words later in the night are a new moment. Without this line, one stuck sentence fills chunk after chunk.

2 Add chunkNight

Now the chunker. Open src/chunk.ts. chunkNight walks one night's records in order and closes a chunk when the next segment won't fit. size counts characters. overlap counts segments.

src/chunk.ts · chunkNight 
1  const chunks: Chunk[] = [];2  let current: SegmentRecord[] = [];3  for (const record of records) {4    // (4) Close the chunk when the next segment won't fit.5    if (current.length > 0 && chunkText([...current, record]).length > size) {6      chunks.push(toChunk(current));7      // (5) Start the next chunk with the last few segments of this one.8      current = overlap > 0 ? current.slice(-overlap) : [];9      // (6) Let go of repeated segments that leave no room for the new one.10      while (11        current.length > 0 &&12        chunkText([...current, record]).length > size13      ) {14        current.shift();15      }16    }17    current.push(record);18  }19  // (7) The last chunk never hits the size limit, so close it here.20  if (current.length > 0) chunks.push(toChunk(current));21  return chunks;
Why each numbered part is there. Point at one to see its lines.
(4) Close before it overflows. The check runs before the segment goes in, so a chunk is whole segments and only goes over size when one segment is longer than that by itself. That segment gets a chunk of its own.
(5) Repeat the last few segments. overlap counts segments, so a question at the end of one chunk and its answer at the start of the next end up together. The price: repeated segments are embedded, stored and paid for twice.
(6) Make room for the new segment. If the repeated segments and the new one are already over size, drop repeated segments from the front. Without this line a big overlap could fill a chunk with nothing new.
(7) Close the last chunk. The loop only closes a chunk when a segment doesn't fit, and a night's last chunk never hits that. Leave this out and the end of every night goes missing.

4 Choose your size and overlap

Open src/choices.ts and fill in CHUNK_SIZE and CHUNK_OVERLAP. The tests don't check what you pick. They run your code at your values and at four other settings, so it has to work for any choice.

  • Smaller chunks match a question tightly, but a fact can get split: a name in one chunk, what happened to it in the next.
  • Bigger chunks keep facts together, but each covers more of the night, its embedding says less about any one moment, and every chunk in a prompt costs more tokens.
  • Overlap of a segment or two rescues a fact split at a boundary. More than that mostly repeats text.

Try 300, 600, 900 or 1,200 characters. The reranker you add in Act 4 reads at most 512 tokens, question and chunk together, so the list stops at 1,200, which leaves room for the question.
