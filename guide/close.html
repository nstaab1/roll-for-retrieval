Take It Home

You built a pipeline that answers questions about two D&D campaigns and keeps the DM's secrets from the players. Push it, and it's yours. Then point it at your own recordings and documents. The loaders, the store and your filter never name a campaign, so your data is new files and new rows, not new code.

Done when

  • your main pushed to your fork
  • one question of your own answered for one member and not another

1 Push main

Everyone pushes the same branch. Commit whatever you have, finished or not. 

git add -A
git commit -m "My workshop"

If git says there's nothing to commit, your work is already in. Push anyway. 

git push

You can't write to the workshop repo, so the first push offers to fork it. Say yes. The fork lands under your account, and from then on origin is your fork and upstream is the workshop. That fork is what you take home.

.env, the cost log and your index stay out of git, so your key never leaves with the fork.

2 Delete the codespace

This step is optional. Once the push is done, the codespace holds nothing your fork doesn't, apart from your key in .env. A stopped codespace still counts against your free storage, so delete it when you're done.

  1. Open github.com/codespaces.
  2. Open the ⋯ menu beside this codespace.
  3. Choose Delete.

To pick it up again, open a new codespace on your fork and copy your key into a fresh .env.

3 Add your own recordings

Your fork is public, and it tracks transcripts/, documents/ and members.json. Once your own data goes in, stop pushing to the fork. To keep a copy on GitHub, create a private repo of your own and push there.

Any recording works. A standup goes through the same command as a game night. Put it in audio/, which git leaves out, so the audio never goes to your fork. Then transcribe it locally, naming its campaign: 

npm run transcribe -- --campaign acme audio/standup.mp3

An hour of audio takes about 12 min with base.en on 4 cores. The command writes the transcript and its meta file beside the recording. The store reads transcripts/, so move both there: 

mv audio/standup.json audio/standup.meta.json transcripts/

Hosted transcription won't do here. It returns no timestamps, so its text can't be cited. A night's chunks get its campaign's party visibility, so everything said in this recording is acme/party.

4 Add your own documents

A document is a Markdown file in documents/ that opens with its visibility. The loader refuses a file without one, so nothing untagged reaches the store. Save this as documents/acme-reorg-plan.md:

documents/acme-reorg-plan.md
---
visibility: acme/leads
---

# Reorg plan

In March the platform group joins the payments team. Dana leads the merged team. We tell everyone at the all-hands on March 3, not before.

Use any visibility you like. The filter compares strings and never names one, so acme/leads needs no code.

One line does still talk about games. answerRules in src/context.ts tells the model it answers about two tabletop campaigns. Answers read better once its first sentence says what your sources are.

5 Say who sees what

members.json gives each role its visibilities and each member their roles. Alice is an engineer and sees the party. Bob is a lead and sees the party and the leads. Add these rows to the end of "roles", with a comma after the row above them:

members.json, roles
"engineer": ["acme/party"],
"lead": ["acme/party", "acme/leads"]

Then add these to the end of "members" the same way:

members.json, members
"alice": ["engineer"],
"bob": ["lead"]

Leave the workshop's rows where they are. Your members hold no Barovia or Toe Wittine role, so the filter keeps the two campaigns out of their answers.

6 Ask as two members

Rebuild your index so it holds the new night and document.

npm run ingest

Ask as Alice:

npm run ask -- --user alice "Which team is the platform group joining?"

The reorg plan isn't among her chunks, so she gets "I don't know" or an answer from the standup. Now ask as Bob: 

npm run ask -- --user bob "Which team is the platform group joining?"

Only Bob's answer cites acme-reorg-plan. That's the same filter you wrote for the DM's notes, on new rows. To score your own data, change the asker in the eval set and write questions you know the answers to, as the eval page says.

The workshop's own tests count the shipped nights and documents, so npm test fails once yours are in. That's expected. Those tests check the workshop's data, not yours.
