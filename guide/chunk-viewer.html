The Chunk Viewer

A chunker decides where one chunk ends and the next begins. Before you write one in Act 2, see what happens when nothing guides that choice. Here is one scene from the windmill finale, the clip you transcribed in Act 1, cut at 3 sizes.

Done when

  • you've found the word the cuts split
  • npm run quest:chunks prints the same cuts
  • you've tried a size of your own

1 Read the cuts

The scene runs from 2:14:03 to 2:16:50 of barovia-2025-12-29, 1,387 characters. Morgantha is forced back from another plane, Freya's parents remember her, and Morgantha is petrified.

The cutter counts characters and ignores where segments end, on purpose.

At 800, the cut lands inside a place name. Chunk 1 ends Elderhe and chunk 2 starts art. Ask where Freya's home is, and neither chunk has the name.

At 200, the cuts land inside 2 words. At 3,000, the whole scene fits in one chunk. Nothing is split, but that one chunk is about everything in the scene at once, so it matches no single question well.

2 Run the side quest 

npm run quest:chunks

It prints the same 3 cuts as tables, one numbered row per chunk, with a line where the page draws each gold break. It reads the transcript on your machine and calls no model, so it spends nothing.

Now try a size of your own. Find a size that keeps the place name whole, then count the words it still splits. 

npm run quest:chunks -- --size 500

3 What your chunker does instead

In Act 2 you write a chunker that closes a chunk between segments, never inside one, so no word is cut in two. A fact can still fall across a break between segments, and that's what overlap is for.
