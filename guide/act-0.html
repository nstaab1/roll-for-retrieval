Roll for Retrieval · Act 0

Set Up the Table

Before anyone rolls, the table gets set. You open the workshop in a codespace, give it your hosted key, and run one command that says whether everything is in place. When it prints READY, you're ready, in the room and at home.

Done when

  • the codespace is open
  • your key is in .env
  • npm run doctor prints READY

1 Open the codespace

On the workshop repo's GitHub page, open Code, then the Codespaces tab, then Create codespace on main. It starts from the workshop image, which already holds Node, ffmpeg, Whisper and its two models, and the reranker. A cold start takes under two minutes.

While it starts, it installs the packages, fetches the 5 sample clips into audio/ and runs the doctor once. Unless you set your key as a Codespaces secret, that first run says the key is missing. Step 2 fixes that.

On your own machine instead? With Docker and VS Code's Dev Containers extension, clone the repo and choose Reopen in Container. It runs the same image, on x64 or an Apple silicon Mac.

2 Add your key

Pre-work gave you an OpenRouter key. Copy the example file, then paste your key after OPENROUTER_API_KEY= in .env. 

cp .env.example .env

With an OpenAI key instead, leave that line empty and use OPENAI_API_KEY=. Either key runs every stage. .env stays out of git. A key set as a Codespaces secret wins over the file.

No key? Ask the presenter for a spare one. It has a spend cap, so it's safe to use for the day.

3 Run the doctor 

npm run doctor

It prints one line per check, then READY or NOT READY. A ready codespace looks like this:

npm run doctor
✓ Node v24.18.0
✓ ffmpeg 5.1.9-0+deb12u1
✓ Whisper base.en model
✓ Whisper small.en model
✓ Reranker model Xenova/ms-marco-MiniLM-L-6-v2
✓ whisper-cli, AVX2 = 1
✓ OpenRouter key from .env
✓ 5 sample clips in audio/
✓ 4 CPU cores
READY
  • A ✗ line ends with Fix: and what to do. Do it, then run the doctor again.
  • The key check makes one real call, an embedding of one word for a tiny fraction of a cent. It's the first line in your cost log.
  • A ! line is a warning, not a failure. Fewer than 4 cores still works. Local transcription is just slower.

The doctor is the only definition of ready. If it says READY and something still breaks, tell the presenter: the doctor has a check missing.

4 Find your way around

  • guide/ holds this page and one page per act. Each act page shows the code to add and why each part is there.
  • src/ has a stub for every piece you write. Until you fill it, it throws a message naming the page and step that has its code.
  • npm test -- 1 runs Act 1's tests, and the same goes for 2 to 4.
